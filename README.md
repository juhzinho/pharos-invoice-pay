# Pharos Invoice Pay

A **SkillEngine skill** for Pharos Pacific that reads an invoice — an e-mail, a PDF, structured JSON or an EIP-681
wallet link — shows where every field came from, **stops on anything that does not add up instead of guessing**, and
prepares the matching payment as an unsigned transaction **with the invoice reference written into it on chain**.

**Live demo:** https://pharos-invoice-pay.vercel.app · **Skill:** [skill/pharos-invoice-pay/SKILL.md](skill/pharos-invoice-pay/SKILL.md)

```
invoice (text | PDF | JSON | EIP-681) ─▶ fields, each with its source line ─▶ checks ─┬─ BLOCKED: what is wrong, where
                                                                                     └─ READY: summary + unsigned tx
                                         the tx data ends with "inv:<reference>"  ·  USDC "once": payable only once
```

## Requirements

| # | Requirement | How it is met |
|---|---|---|
| 01 | Extracts payee, amount, token or currency, and reference from at least 2 invoice formats | **Four**: plain text / e-mail, **PDF** (pdf.js; text rebuilt into lines with columns kept apart), **JSON** (a simple schema or UBL-style keys such as `LegalMonetaryTotal.PayableAmount`, `PayeeParty.EndpointID`) and **EIP-681** payment links. Every field is returned with its source — `line 19: “Amount due: 1,250.00 USD”`, a JSON path, or a URI parameter — plus subtotal, tax, line items, dates, network and amount in words when present ([formats](skill/pharos-invoice-pay/references/formats.md)). |
| 02 | Flags mismatches or missing fields instead of guessing | Two values for one field are a **conflict**, never a choice. Blocks: missing fields; a checksum **typo** in the address; **a known vendor asking to be paid at a new address** (the vendor book); subtotal + tax ≠ total; line items ≠ subtotal; total ≠ amount due; **words ≠ digits**; an **ambiguous separator** (`1.850`); a currency with no token (EUR is never converted at a guessed rate; USD is paid in USDC only while the Chainlink USDC/USD feed is within 0.5 %); the wrong network; the payer's balance; **already paid**. Ambiguous dates (`04.11.2026`) and overdue invoices are warned. In the demo, 7 of the 10 sample invoices are blocked, each for its own reason ([checks.json](public/runs/checks.json)). |
| 03 | Produces a payment summary and an unsigned transaction that includes the invoice reference | A summary in plain words (“Pay 1,250 USDC to Acme Design Studio (0x7998…1D18) for invoice INV-2026-0142, due 2026-11-30…”) and the unsigned transaction whose data ends with **`inv:<reference>`** after the call's ABI arguments — token contracts ignore trailing calldata (checked on Pacific: +258 gas), explorers show it, and `verify --tx` reads it back. For USDC the default is **“once”**: an EIP-3009 authorization whose nonce is the invoice's fingerprint `keccak(payee, reference)`, so the same invoice number to the same payee can be paid **only once**. |
| 04 | Includes a demo with sample invoices | [invoices/](invoices/): 10 samples in the four formats (3 clean, 7 with one real problem each) + a vendor book, regenerated by `scripts/make-invoices.js`. The site checks all ten live and lets you check your own (text, JSON or PDF). The three clean ones were **paid on a fork and read back from chain** ([fork-proof.json](public/runs/fork-proof.json)). |

## The ten samples, checked live on Pacific ([checks.json](public/runs/checks.json))

| invoice | format | result |
|---|---|---|
| acme-design.txt | e-mail | **ready** — USD paid 1:1 in USDC (USDC/USD 0.9997 on the Chainlink feed); payee matches the vendor book |
| northwind-hosting.pdf | PDF (two columns) | **ready** — 3 line items add up to the subtotal and the total |
| lumen-payment-request.txt | EIP-681 | **ready** — 320 USDC from `uint256=320000000`, matching the text around it |
| acme-design-new-wallet.pdf | PDF | **blocked** — “Acme Design Studio” asks to be paid at an address that is not Acme's on file |
| orbit-cloud.json | JSON (UBL keys) | **blocked** — subtotal 900, payable 950, no tax or charge explaining it |
| harbor-words.txt | e-mail | **blocked** — 1,850.00 in digits, “one thousand five hundred eighty dollars” in words |
| atlas-typo.txt | e-mail | **blocked** — the payee address's checksum does not match: a mistyped character |
| ambiguous-amount.txt | e-mail | **blocked** — “1.850” could be 1850 or 1.85 |
| berlin-euro.txt | e-mail | **blocked** — EUR (and its date 04.11.2026 is warned as day/month ambiguous) |
| missing-reference.json | JSON | **blocked** — no invoice number |

The payer is a real Pacific wallet (read-only); the vendor addresses are demo EOAs derived from the vendor names.

## Paid on a fork, read back from chain ([fork-proof.json](public/runs/fork-proof.json))

`npm run invoice -- demo` forks Pacific mainnet (block 22,575,057 for the recorded run) and funds a fresh test
payer on the fork only:

| invoice | mode | sent by | read back from chain |
|---|---|---|---|
| Acme (e-mail) | once (EIP-3009) | a relayer | memo `inv:INV-2026-0142` ✓ payee ✓ amount ✓ — 103,092 gas |
| Northwind (PDF) | direct (transfer + memo) | the payer | memo `inv:NW-88213` ✓ payee ✓ amount ✓ — 62,363 gas |
| Lumen (EIP-681) | once (EIP-3009) | an unrelated account | memo `inv:LT-5521` ✓ payee ✓ amount ✓ — 103,008 gas |

Then: Acme's invoice checked again is **blocked as already paid** — the check finds the paying transaction by a
binary search on `authorizationState` — and the same authorization re-sent anyway is refused by USDC
(`FiatTokenV2: authorization is used or canceled`). Acme's payment checked against Lumen's invoice does not match
(reference, payee and amount differ).

## Run it

```bash
npm install
npm run invoice -- check invoices/acme-design.txt --payer 0x6ea08ca8f313d860808ef7431fc72c6fbcf4a72d
npm run invoice -- check invoices/northwind-hosting.pdf --mode direct     # unsigned transfer + memo
npm run invoice -- check invoices/acme-design-new-wallet.pdf              # exit 3: blocked, with the reason and the lines
npm run invoice -- assemble .invoice/INV-2026-0142.json --sig 0x…         # "once": the payer's signature → unsigned tx
npm run invoice -- verify --tx 0x… --invoice invoices/acme-design.txt     # memo + what moved + match
npm run invoice -- demo                                                    # the fork run above (Anvil comes via npm)
npm run web                                                                # the demo site on http://localhost:3150
```

Exit codes: `0` ready or review · `3` blocked / does not match · `2` a mistake in the input · `1` the chain or RPC
failed. `--json` prints everything machine-readable (for another agent). Settings: [.env.example](.env.example).
